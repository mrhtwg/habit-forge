## EARS 原则说明

本文档中所有功能需求均遵循 EARS（Easy Approach to Requirements Syntax）原则标注类型：

| 类型 | 含义 | 模板 |
|------|------|------|
| **Ubiquitous（普遍约束）** | 系统始终满足的约束 | 系统应当始终… |
| **Event-driven（事件驱动）** | 由事件触发的行为 | 当[事件]发生时，系统应当… |
| **Unwanted（异常/故障）** | 异常/故障处理 | 若[异常条件]，则系统应当… |
| **State-driven（状态驱动）** | 在特定状态下的行为 | 当处于[状态]时，系统应当… |
| **Optional（可选功能）** | 可选功能 | 在[功能开启]的情况下，系统应当… |

## 1. 背景（Background）

### 1.1 问题陈述

海外市场对「将现实生活目标管理（Habit / Goal / Todo）游戏化」的需求已被验证：竞品 Habitica 年收入约 530 万美元、运营超 13 年，Finch、Fabulous 等同赛道产品持续增长。然而 Habitica 存在明显体验断层：

- 视觉停留 2013 年复古像素风，与现代移动端审美脱节
- 移动端本质是 Web 包装，交互不够原生流畅
- RPG 深度有限（仅数值变化，无角色养成沉浸感）
- 新手引导缺失，功能堆叠导致上手门槛高

### 1.2 产品机会

HabitForge 以「现代原生移动端体验 + 3D 角色养成」切入，对标 Habitica 但补齐体验短板：

- 3D GLB 角色（可旋转/缩放），情感锚点更强
- Flutter 原生手势交互（滑动完成任务）
- 暗黑沉浸视觉 + 华丽奖励动效
- 4 步极简引导，首屏即核心操作

### 1.3 MVP 决策依据

首个独立项目，需严格控制范围以规避「烂尾」风险（独立开发者首作完成率约 40%）。MVP 聚焦单一核心闭环验证：

```
创建现实任务 → 完成任务获得 EXP/金币 → 角色升级 → 外观解锁 → 继续创建任务
```

## 2. 目标（Goals）

### 2.1 业务目标

| 编号 | 目标 | 衡量指标 | 目标值（MVP 上线后 3 个月） |
|------|------|---------|--------------------------|
| G1 | 验证核心闭环吸引力 | D30 留存率 | ≥ 15% |
| G2 | 验证任务完成驱动机制 | 周任务完成率 | ≥ 70% |
| G3 | 验证 3D 角色的情感价值 | 角色面板日均访问次数 | ≥ 1.5 次/DAU |
| G4 | 建立早期用户基础 | 累计注册用户 | ≥ 2,000 |
| G5 | 验证付费意愿（为 v2.0 铺垫） | 免费→付费转化率 | 观察为主，目标 2-5% |

### 2.2 用户目标

| 用户目标 | 对应功能 |
|---------|---------|
| 用有趣的方式坚持习惯 | 任务系统 + 游戏化反馈 |
| 看到自己的成长 | 角色升级 + 数据看板 |
| 有视觉成就感 | 3D 角色 + 外观解锁 |
| 轻量无负担 | 极简引导 + 无社交压力 |

### 2.3 非目标（Out of Scope）

MVP **不包含**以下功能（明确砍掉，v2.0+ 规划）：

- 技能树、宠物系统、公会系统、Boss 战、好友系统
- 装备属性系统（MVP 仅外观，不影响数值）
- 内购支付（MVP 商店仅消耗游戏金币）
- 多语言（仅英文）、暗黑模式切换（仅暗色主题）
- 可穿戴设备集成、AI 习惯推荐

## 3. 用户画像与用户故事（User Stories）

### 3.1 目标用户画像

| 维度 | 描述 |
|------|------|
| **核心用户** | 18-35 岁，海外（英语区为主），对 RPG/游戏有偏好 |
| **痛点** | 传统待办/习惯 App 枯燥、难坚持；普通游戏无法迁移到现实 |
| **使用场景** | 早晨规划一天任务、工作间隙打卡、睡前回顾 |
| **动机** | 自我提升 + 游戏化反馈带来的多巴胺 |
| **技术环境** | iOS 14+ / Android 8+，中端以上设备 |
| **后端** | Flutter 直连 Firebase（Firebase Auth + Firestore），零服务器成本 |

| 编号 | 作为…我想要…以便… | 优先级 |
|------|------------------|--------|

| US-02 | 作为用户，我想通过滑动手势快速完成任务，以便操作流畅无摩擦 | P0 |
| US-03 | 作为用户，我想在完成任务后看到即时奖励（EXP/金币 + 动效），以便获得正反馈 | P0 |
| US-04 | 作为用户，我想看到我的 3D 角色随等级成长，以便获得视觉成就感 | P0 |
| US-05 | 作为用户，我想用金币在商店购买外观改变角色形象，以便个性化表达 | P1 |
| US-06 | 作为用户，我想查看我的习惯完成率和趋势，以便了解自己的进展 | P1 |
| US-07 | 作为用户，我想解锁成就徽章，以便获得里程碑认可 | P1 |
| US-08 | 作为用户，我想跨设备同步数据，以便换手机不丢失进度 | P1 |
| US-09 | 作为用户，我想自定义任务难度/标签/奖励，以便匹配我的目标 | P0 |

## 4. 功能需求（Functional Requirements）

### 4.1 账户与用户系统

#### FR-ACC-01 注册与登录

| 类型 | 需求描述 |
|------|---------|
| **Ubiquitous** | 系统应当始终允许用户通过邮箱或 Google/Apple 账号登录以访问云同步功能。 |
| **Event-driven** | 当用户首次打开 App 且未登录时，系统应当展示登录/注册入口。 |
| **Event-driven** | 当用户使用 Google/Apple 授权登录时，系统应当自动创建账户（若不存在）并跳过邮箱验证步骤。 |
| **Unwanted** | 若邮箱注册时密码强度不足（< 8 字符或纯数字），则系统应当阻止提交并提示具体要求。 |
| **Unwanted** | 若第三方登录授权被用户取消或失败，则系统应当返回登录页并提示可重试。 |
| **Optional** | 在用户同意隐私政策的前提下，系统应当记录基本分析事件以支持产品决策。 |

#### FR-ACC-02 云同步

| 类型 | 需求描述 |
|------|---------|
| **Ubiquitous** | 系统应当始终在用户登录状态下将所有任务/角色数据实时同步至云端。 |
| **Event-driven** | 当设备网络恢复时，系统应当自动重试之前失败的同步操作。 |
| **State-driven** | 当处于离线状态时，系统应当允许本地操作并将变更排队，待联网后同步。 |
| **Unwanted** | 若云端数据与本地数据冲突（如多设备同时编辑），则系统应当以最后写入时间为准覆盖，并提示用户。 |

### 4.2 新手引导（Onboarding）

#### FR-ONB-01 引导流程

| 类型 | 需求描述 |
|------|---------|
| **Event-driven** | 当用户首次完成注册并进入 App 时，系统应当启动 4 步引导流程。 |
| **Event-driven** | 当用户在 Step 2 选择职业（Warrior/Mage/Ranger）并确认时，系统应当创建对应 3D 角色并保存选择。 |
| **Event-driven** | 当用户在 Step 3 创建至少一个习惯时，系统应当将其加入今日任务列表。 |
| **State-driven** | 当引导进行到任意步骤时，系统应当允许用户点击「跳过」直接结束引导进入主页。 |
| **Unwanted** | 若用户在引导中途退出 App，则系统应当在下次打开时从中断步骤继续，而非重新开始。 |
| **Ubiquitous** | 系统应当始终在用户完成引导后将 `onboarding_completed = true` 写入用户配置，不再展示引导。 |

### 4.3 任务系统

#### FR-TSK-01 任务类型

| 类型 | 需求描述 |
|------|---------|
| **Ubiquitous** | 系统应当始终支持三种任务类型：习惯（Habit）、每日任务（Daily）、待办（ToDo）。 |
| **Event-driven** | 当用户创建类型为 Habit 的任务时，系统应当支持正负向标记（正向+EXP / 负向-HP / 双向±）。 |
| **Event-driven** | 当用户创建类型为 Daily 的任务时，系统应当要求设置重复规则（每日/特定星期）和时间。 |
| **Event-driven** | 当用户创建类型为 ToDo 的任务时，系统应当允许设置截止日期（可选）和优先级（高/中/低）。 |
| **Ubiquitous** | 系统应当始终为每条任务记录创建时间、难度（易/中/难）、标签和自定义 EXP/金币奖励值。 |

#### FR-TSK-02 任务完成

| 类型 | 需求描述 |
|------|---------|
| **Event-driven** | 当用户对任务执行左滑手势（或点击完成按钮）时，系统应当标记为已完成并触发奖励计算。 |
| **Event-driven** | 当习惯任务被标记正向（+）时，系统应当增加对应 EXP 和金币，并增加连胜计数。 |
| **Event-driven** | 当习惯任务被标记负向（−）时，系统应当扣减 HP（若配置惩罚），并重置连胜计数。 |
| **Event-driven** | 当每日任务在到期前未完成且超过截止时间时，系统应当自动标记为「过期」并扣减 HP。 |
| **State-driven** | 当每日任务处于「已完成」状态时，系统应当展示划线样式且不可再次左滑完成。 |
| **Unwanted** | 若用户在网络异常时完成任务，则系统应当先本地记录完成状态，联网后同步并补发奖励。 |
| **Optional** | 在用户开启「触觉反馈」的情况下，系统应当在完成任务时触发成功触觉。 |

#### FR-TSK-03 任务管理

| 类型 | 需求描述 |
|------|---------|
| **Event-driven** | 当用户长按任务项时，系统应当弹出操作菜单（编辑/删除/查看详情）。 |
| **Event-driven** | 当用户删除任务时，系统应当二次确认（防止误删），确认后从列表和云端移除。 |
| **Event-driven** | 当用户对任务执行右滑手势时，系统应当标记为「跳过/延后」并变灰。 |
| **Ubiquitous** | 系统应当始终支持按标签（All/Health/Work/Learn 等）筛选任务列表。 |

#### FR-TSK-04 连胜（Streak）

| 类型 | 需求描述 |
|------|---------|
| **Ubiquitous** | 系统应当始终为每条习惯/每日任务维护连胜天数计数。 |
| **Event-driven** | 当用户连续完成同一任务达到 7 天时，系统应当触发「连胜火焰」视觉特效。 |
| **Unwanted** | 若用户在某一日未完成每日任务，则系统应当将该任务连胜计数重置为 0。 |

### 4.4 角色与成长系统

#### FR-CHR-01 角色展示

| 类型 | 需求描述 |
|------|---------|
| **Ubiquitous** | 系统应当始终在主页展示用户 3D 角色（GLB 模型），支持单指旋转和双指缩放。 |
| **Event-driven** | 当用户双击主页角色时，系统应当全屏打开角色面板。 |
| **State-driven** | 当角色处于空闲状态（无新操作 5 秒）时，系统应当播放 Idle 待机动画。 |
| **Optional** | 在设备性能允许的情况下，系统应当启用角色自动缓慢旋转以增添生动感。 |

#### FR-CHR-02 等级与属性

| 类型 | 需求描述 |
|------|---------|
| **Ubiquitous** | 系统应当始终根据累计 EXP 计算用户等级（1-50 级），并展示 EXP 进度条。 |
| **Event-driven** | 当累计 EXP 达到当前等级阈值时，系统应当触发升级：全屏金色光效 + 角色 Victory 动画 + 属性点 +1。 |
| **Event-driven** | 当用户在角色面板分配属性点时，系统应当实时更新 STR/INT/AGI/DEF/VIT/LUK 数值。 |
| **Unwanted** | 若用户尝试分配超过可用点数的属性点，则系统应当阻止并提示「无可用点数」。 |
| **State-driven** | 当角色等级 < 10 时，系统应当仅解锁基础外观；等级 ≥ 10 解锁稀有外观（商店可购）。 |

#### FR-CHR-03 HP 与死亡

| 类型 | 需求描述 |
|------|---------|
| **Ubiquitous** | 系统应当始终维护角色 HP（上限 100），初始值为 100。 |
| **Event-driven** | 当每日任务过期或负向习惯触发导致 HP 降低时，系统应当播放屏幕红边闪烁 + 角色 Hit 动画。 |
| **Event-driven** | 当 HP 降至 0 时，系统应当播放角色倒地动画 + 红色遮罩，并展示「恢复倒计时」（30 分钟后 HP 恢复至 50%）。 |
| **State-driven** | 当 HP < 30% 时，系统应当持续显示红色脉冲边框和角色受伤姿态。 |
| **Unwanted** | 若 HP 恢复倒计时期间用户再次触发 HP 降低，则系统应当保持死亡状态直至倒计时结束。 |

### 4.5 奖励与货币系统

#### FR-RWD-01 货币

| 类型 | 需求描述 |
|------|---------|
| **Ubiquitous** | 系统应当始终维护两种游戏货币：金币（Gold，任务奖励）和宝石（Gem，稀有掉落，MVP 仅通过成就获得）。 |
| **Event-driven** | 当用户完成任务时，系统应当根据任务难度和类型发放对应 EXP 和金币。 |
| **Event-driven** | 当用户解锁指定成就时，系统应当发放宝石奖励（如首次升级奖励 5 宝石）。 |
| **Unwanted** | 若奖励计算出现异常（如负值或溢出），则系统应当记录错误日志并回滚至上一已知正确状态。 |

#### FR-RWD-02 奖励展示

| 类型 | 需求描述 |
|------|---------|
| **Event-driven** | 当任务完成奖励发放时，系统应当展示奖励弹窗（EXP +N / 金币 +N 飘字动画 + 音效）。 |
| **State-driven** | 当奖励弹窗展示时，系统应当暂停底层页面交互直至用户关闭或 2 秒后自动消失。 |

### 4.6 商店与外观

#### FR-SHP-01 商店浏览与购买

| 类型 | 需求描述 |
|------|---------|
| **Ubiquitous** | 系统应当始终在 Forge Tab 提供外观商店，按类别（Appearance / Equipment）展示可购物品。 |
| **Event-driven** | 当用户点击购买且金币充足时，系统应当扣减金币、将物品加入背包并播放购买动效。 |
| **Event-driven** | 当用户点击购买但金币不足时，系统应当提示「金币不足」并高亮差额。 |
| **Unwanted** | 若购买过程中网络中断导致扣款成功但物品未到账，则系统应当在下次同步时校验并补发（幂等保障）。 |

#### FR-SHP-02 装备与外观应用

| 类型 | 需求描述 |
|------|---------|
| **Ubiquitous** | 系统应当始终将已购买的外观物品保存在用户背包中，可重复穿戴/卸下。 |
| **Event-driven** | 当用户在角色面板点击装备槽并选择物品时，系统应当实时更新 3D 角色 GLB 模型外观。 |
| **Event-driven** | 当用户卸下装备时，系统应当恢复角色默认外观。 |
| **Ubiquitous** | 系统应当始终确保 MVP 阶段的装备仅影响视觉外观，不改变任何战斗/属性数值。 |

#### FR-SHP-03 每日特惠

| 类型 | 需求描述 |
|------|---------|
| **Event-driven** | 当每日 0 点（用户本地时区）刷新时，系统应当生成一组限时折扣物品（如 40% OFF），展示 24 小时倒计时。 |
| **State-driven** | 当特惠倒计时结束时，系统应当自动下架当前特惠并等待次日刷新。 |

### 4.7 成就系统

#### FR-ACH-01 成就定义与解锁

| 类型 | 需求描述 |
|------|---------|
| **Ubiquitous** | 系统应当始终维护成就列表（如 First Blood / Hot Streak / Task Master 等），记录解锁状态。 |
| **Event-driven** | 当用户达成成就条件（如首次完成任务）时，系统应当解锁对应成就并展示全屏解锁动画。 |
| **Event-driven** | 当用户解锁成就时，系统应当发放对应宝石奖励（若有）。 |
| **State-driven** | 当成就已解锁时，系统应当在成就墙以高亮/彩色展示，未解锁以灰色展示。 |
| **Unwanted** | 若用户在离线状态达成成就条件，则系统应当在联网同步后补发解锁和奖励。 |

### 4.9 设置

#### FR-SET-01 偏好设置

| 类型 | 需求描述 |
|------|---------|
| **Ubiquitous** | 系统应当始终允许用户配置：通知开关、触觉反馈开关、音效开关。 |
| **Event-driven** | 当用户修改偏好设置时，系统应当即时生效并持久化。 |

## 5. 流程说明（Flow Description）

### 5.1 核心闭环流程

```
┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│ 创建任务    │───▶│ 完成任务    │───▶│ 获得奖励    │
│ (US-01/09) │    │ (US-03)    │    │ (EXP/金币) │
└─────────────┘    └─────────────┘    └──────┬──────┘
                                               │
                          ┌────────────────────┘
                          ▼
                   ┌─────────────┐    ┌─────────────┐
                   │ 角色升级    │───▶│ 外观解锁    │
                   │ (US-04)    │    │ (US-05)    │
                   └─────────────┘    └─────────────┘
```

### 5.2 新用户首次流程

```
注册/登录 → 引导 Step1(Welcome) → Step2(选职业) → Step3(建习惯) → Step4(Ready) → 主页
```

### 5.3 任务完成奖励流程

```
左滑/点击完成 → 本地标记完成 → 计算 EXP/金币 → 展示奖励弹窗
     → 更新角色 EXP 进度条 → [若达阈值] 触发升级 → 云同步
```

### 5.4 HP 归零恢复流程

```
HP 降至 0 → 角色倒地动画 + 红色遮罩 → 展示 30 分钟倒计时
     → 倒计时结束 → HP 恢复至 50 → 角色复活动画 → 恢复正常操作
```

## 9. 边界场景与异常状态（Edge Cases）

| 场景 | 系统行为 |
|------|---------|
| 网络完全断开 | 本地操作正常，变更排队，联网后同步 |
| 多设备同时编辑 | 以最后写入时间覆盖，提示用户 |
| 任务奖励计算异常 | 记录错误日志，回滚至上一正确状态 |
| 购买扣款成功但物品未到账 | 下次同步校验补发（幂等） |
| HP 倒计时中再次扣血 | 保持死亡状态至倒计时结束 |
| 引导中途退出 | 下次从中断步骤继续 |
| 3D 模型加载失败 | 展示占位角色（默认几何体）+ 错误日志 |
| 用户删除账户 | 7 天冷静期后永久删除，云数据清除 |
| 极低内存设备 | 降低 3D 渲染分辨率/帧率，保证可用 |
| 时区跨越 | 每日任务重置以用户本地时区 0 点为准 |

## 11. 非功能性需求（Non-Functional Requirements）

| 类别 | 需求 |
|------|------|
| 可用性 | 首屏操作无需教程即可理解（图标+文字双重表达） |
| 无障碍 | 支持屏幕阅读器（Semantics）、动态字体 1.5x、减弱动效设置 |

| 性能 | 见 8.2 性能验收 |
| 可维护性 | 模块化架构；关键逻辑单元测试覆盖 ≥ 60% |
| 国际化 | 代码层做好 i18n 准备（MVP 仅 en），便于 v2.0 扩展 |
| 成本 | 后端使用 Firebase Spark 免费套餐；月运营成本 ≤ $0（零服务器） |
